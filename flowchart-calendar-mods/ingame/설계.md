## 2. 이동 — `KR_ChartRun(번호)`

원작 `C_TestScenario@ExecScenario` 의 본체를 **글자 그대로** 옮긴다 [확인].

```
LSys3xScript::PrepareSys("ＥＶ／元／E%05d")   // m_IsSysScenario=1, m_FuncName=그 이름
LSys3xScript::RunEvent()                        // 엔진이 델리게이트를 만들어 부른다
■ＡＤＶ消し(1, 0)
```

- `PrepareSys` 를 쓰면 이름에 접두어를 다시 붙이지 않으므로 **전체 이름**을 넘겨야 한다.
- `_AdjustOriginalName` 예외 두 개(`E01707 → 01707`, `E02132 → 02132`)를 잊지 말 것. 초안에서는 원작 함수를 그대로 불러 처리한다.
- 번호 → 이름은 원작 `LSys3xScript::GetLabelName` 을 쓴다(1706 만 `E%04d` 인 예외가 이미 들어 있다).

### 2.1 반드시 알려야 할 부작용 [확인]

1. **사슬이 돈다.** 릴리스에서는 `■デバッグ／シナリオジャンプ無視確認` 이 언제나 거짓이라 `g_EvResult` 사슬을 끌 수 없다. 한 장면을 부르면 이어지는 장면까지 잇달아 돈다(사슬 129개). 차트의 방문 순서는 이걸 한 덩어리로 본다.
2. **읽음·회상이 등록된다.** 이벤트가 `■ＡＤＶ制御` 를 부르는 순간 `_EV_TABLE` 에 들어가고 회상도 열린다.
3. **친밀도가 오른다.** 친밀도 도우미가 든 25개 이벤트는 그대로 오른다.
4. **문맥은 안 맞춘다.** 날짜·파티·친밀도를 맞춰 주지 않는다. 원작 실행기도 안 한다. 배경·인물 그림은 이벤트가 자기 안에서 준비하므로 장면 자체는 뜬다 [가설 — 실기 미확인].

→ 화면 문구에 「검수용 슬롯을 따로 쓰세요」를 넣는다. **사용자 세이브를 자동으로 백업하거나 고치지 않는다.**

### 2.2 요청 → 소비 (설계도 7.1)

UI 에서는 슬롯에 번호만 넣고(`KR_ChartAsk`), 게임 루프의 안전한 지점에서 소비한다(`KR_ChartConsume`).
끼울 자리 후보 [가설 — Codex 와 맞춰야 함]:

- 모드 탭 버튼을 누른 직후(옵션 화면은 게임 씬 밖이라 `RunEvent` 가 배경을 건드릴 수 있다 → 위험),
- 본거지 화면의 한 프레임 끝(`C_SceneGame` 의 업데이트 끝),
- 가장 안전한 것은 **원작 실행기가 실행되는 것과 같은 지점**, 곧 `C_SceneGame` 이 살아 있는 동안이다.

권하는 안: 모드 탭에서 번호를 받고 옵션을 닫은 뒤, `C_SceneGame` 의 업데이트 끝 훅에서 `KR_ChartConsume()` 한 번.

### 2.3 슬롯

공통 설정 슬롯 72~79 는 Codex 가 모드 옵션에 쓰고 있다. 차트는 **슬롯 80** 하나만 쓴다(요청 번호). 충돌 여부는 Codex 확인 필요.

## 4. 진행 내보내기

### 4.1 막힌 곳 [확인]

```
AFL_TextFile_WriteAll(fileName, text):
    if (!system IsDebugMode) return 0;      ← 릴리스에서 여기서 끝
    return CALLHLL TextFile WriteAll;
AFL_TextFile_CreateWriter(fileName):
    if (!system IsDebugMode) return 0;      ← 같음
```

### 4.2 길 A — jam 브리지로 HLL 을 직접 부른다 [추천]

`KR_ChartWriteFile(string, string)` 의 본문을 jam 브리지로 채운다.

```
FUNC <id>
	.LOCALREF fileName
	.LOCALREF text
	CALLHLL TextFile WriteAll 0
	RETURN
ENDFUNC KR_ChartWriteFile
```

- 스크립트 게이트만 건너뛴다. 엔진이 새로 하는 일은 없다.
- **위험**: `TextFile` HLL 이 릴리스 실행 파일에도 들어 있는지는 확인 못 했다 [가설]. AIN 의 HLL 표에 선언은 있다(그래서 `CALLHLL` 이 컴파일된다). 실기에서 한 번 눌러 보면 바로 갈린다.
- 쓰는 곳: 세이브 폴더 **밖** `…\AliceSoft\<게임>\flowchart_progress.json`(설계도 D8). `AFL_TextFile_*` 의 상대 경로 기준이 세이브 폴더인지 실행 폴더인지도 실기 확인 항목이다.

### 4.3 길 B — 파일을 안 쓴다

모드 탭에 목록을 띄우고 사용자가 차트에서 번호를 직접 체크하게 한다. 파일 쓰기가 막혀도 되지만 1,164개는 손으로 못 한다. **길 A 가 실패했을 때만**.

### 4.4 내보낼 값 [확인]

| 항목 | 어디서 |
|---|---|
| 이번 판 읽음 | 전역 `array<string> N_ScenarioRegister::detail::_EV_TABLE` 전체(문자열 그대로) |
| 개수 | `LEventFlag::GetCountOnce()` |
| 누적(회상 76칸만) | `LEventFlag::GetTotal("Exxxxx")` |
| 시스템 플래그 101칸 | `■システムフラグ／取得(i)` |
| 날짜 | `Flags.Date` 의 `월`(26450) · `日`(26453) · `週`(26456) |
| 친밀도 | `LAbility::At(p)->GetFeeling()`(27310), 인물 2~8 |
| 루트 | `LAbility::At(p)->IsTurning()`(27404), 인물 2~5 |

차트가 읽는 꼴(`chart/yoru_flowchart.html` 이 이미 받아들인다):

```json
{"schema":"yoru-progress.v1","date":[6,12],"week":3,
 "seen_once":[10001,10022], "seen_total":[10001],
 "sys_flags":[...], "feeling":{"2":31}, "turning":[2]}
```

- 게임 쪽은 이름(`ＥＶ／元／E10001`)으로 들고 있으므로, 내보낼 때 번호로 바꾸거나 차트 쪽에서 이름을 번호로 바꾼다. **차트 쪽에서 바꾸는 게 낫다** — 게임 안 문자열 처리가 비싸다. (현재 HTML 은 번호 배열만 읽는다. 이름 배열도 받게 하는 건 한 줄이다.)

## 5. 잠금 기준을 D4′ 로 [확인에 따른 변경 제안]

- `seen_total` 은 회상 76칸에만 값이 있다 → 그것만으로는 차트가 거의 다 잠긴 채로 남는다.
- **추천**: `_EV_TABLE`(이번 판 읽음)으로 잠금을 풀고, 회상 76칸은 `GetTotal` 로 「예전 판에서도 봤음」을 덧붙인다.
- 위험: 새 판을 시작하면 `_EV_TABLE` 이 비므로 차트가 다시 잠긴다. 진행 파일을 **합치는** 기능(차트 쪽에서 여러 파일 OR)을 두면 된다 [추천안].

## 6. 정적 게이트 목록 (Phase 2 후보를 만들 때)

Codex 가 쓰는 것과 같게 간다.

1. 입력 해시: 바탕 AIN 이 `ui_cumulative/current.json` 이 가리키는 판과 같은가.
2. opcode 감사: 새로 넣은 함수에 허용 밖 opcode 가 없는가.
3. 함수 서명·전역·구조체 보존: 원본에 있던 것이 하나도 안 없어졌는가(함수 하나 빼서 걸리는지 증명).
4. `MSG` 1번·`STR` 0번 불변: 텍스트를 건드리지 않았는가.
5. PACT 되읽기 exact: 모드 탭 파일을 다시 풀었을 때 바이트가 같은가.
6. 글꼴 문자집합: 새 문구의 글자가 전부 글꼴 표 안인가([[engine-text-must-fit-font-map]] — 도화이담에서 `|` 하나로 죽었다).
7. 설치·복구 fixture: 설치 전/후 해시와 되돌리기.
8. 차트 전용: `KR_Chart*` 함수가 원작 함수를 **덮어쓰지 않는가**(새 번호로만 추가).

게이트마다 결함을 심어 실제로 걸리는지 본다.

## 8. 사용자가 실기에서 확인해 줘야 하는 것

1. `CALLHLL TextFile WriteAll` 이 릴리스에서 실제로 파일을 쓰는가(길 A 성패).
2. 그 상대 경로의 기준 폴더가 어디인가.
3. `KR_ChartRun` 으로 부른 장면이 본거지 화면에서 제대로 뜨고, 끝난 뒤 원래 화면으로 돌아오는가.
4. 사슬이 이어질 때 화면이 어색하지 않은가(특히 배경·달력 표시).
5. 슬롯 80 이 Codex 의 다른 기능과 겹치지 않는가.
