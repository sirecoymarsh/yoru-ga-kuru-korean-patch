## 4. 폴링 위치와 비용

- RunHome 반복은 메뉴 창의 클릭 대기(`AFL_Parts_WaitForClick`) 안에서 멈춰 있으므로 「반복마다」 보면 메뉴바를 눌러도 다음 선택까지 처리되지 않는다. 그래서 **메뉴 창의 프레임 콜백**에서, **본거지 첫 메뉴가 떠 있을 때만**(KR_MHomeRun 이 무장한 동안) 본다.
- 비용(음소거 사본, 본거지 첫 메뉴, 5,000번씩): `KR_MPending` 0.125 ms/회(존재 검사 2번), 무장된 `KR_MTick` 0.124 ms/회, `ExistFile`(있는 파일) 0.070 ms/회, 세션 변수 읽기 0.0014 ms/회. 무장 안 된 창에서는 세션 변수 읽기 한 번뿐.
- 프레임 시간(홈 메뉴, 180프레임씩): 무장 16.9 ms/프레임, 해제 17.2 ms/프레임 — 차이 없음(동기 기다림이 지배). 매 프레임 0.12 ms(60 fps 예산의 0.7%)라 **n프레임마다로 줄이지 않았다.**
- 쓰기 → 창이 보이기까지 약 0.5 s(메뉴 창 닫힘 + 안내 창 열림 연출).

## 5. 종료 경로

- 게임의 「게임 종료」: 타이틀 끝내기 = `Ａ＿ゲーム終了`, 메뉴바 닫기 = `_system::detail::ProcessSystemMessage` 7번. 둘 다 **확인(창 설정 4번, 기본 켬이면 일본어 MessageBox 「ゲームを終了しますか？」) → `system.Exit(0)` → `system.Peek` 반복**이다.
- `KR_MExit` 은 그 **확인 뒤 부분**을 그대로 부른다(`system.Exit(0)` + `while(true) system.Peek()`). 확인은 게임 안 예/아니요 창(과 후크의 네이티브 1차 확인)이 대신한다 — `Ａ＿ゲーム終了` 자체를 부르면 일본어 MessageBox 로 세 번째 확인이 뜬다(탐침 실행기는 MessageBox 를 잡아 끊는다). 저장 호출 없음(정적: KR_MHomeRun · KR_MTick 에서 닿는 함수 42개 중 저장 · 불러오기 · 설정 · 타이틀 호출 0, `system.Exit` 는 KR_MExit 하나).
- 네이티브: run A(예 → reset) · run B(예 → restore) 모두 「ANSWER YES」 줄 바로 뒤 프로세스가 끝났다(그 뒤 탐침 틱 기록 없음; 게임이 계속됐다면 다음 프레임에 「NOT EXITED」를 남긴다), 엔진 오류 · MessageBox 없음. **프로세스 종료 코드는 `system.Exit` 의 인자를 싣지 않는다** — 탐침 자신의 `system.Exit(77)` 도 0 으로 끝났다(통합 탐침 첫 실행) — 그래서 어느 종료였는지는 종료 코드가 아니라 기록의 마지막 줄로 가른다. 종료 때 엔진이 스스로 쓰는 파일(`CommonSystemData.sav` · `Volume.sav` · `WindowSetting.sav`, `Backup\<시각>\` 에 AFConfig + NightRAF* 5개) = r21 을 전혀 안 쓰고 `system.Exit(0)` 만 한 대조 실행(run C)과 **같은 집합**.
