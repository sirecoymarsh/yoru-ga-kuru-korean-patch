## r20 요구 (2026-09-27 20시, 설계: Claude / 구현: Opus, r19 다음) — 특훈 상대·던전 멤버 고를 때 「몇 번 갔나 · 남은 이벤트」

### 사용자 요청·결정 (09-27 20시)
「특훈이나 던전 멤버 선택을 할 때 이 루트에서 지금껏 몇 번씩 갔나, 남은 이벤트 몇 개 있나를 표시」. 배치: **던전 멤버 고르기(`C_SceneHomebase@RunMember`) → 상태 창(`C_HomeStatusView`)에 「이벤트」 쪽 추가**, **특훈 상대 고르기(`C_SceneTraining@RunSelectPartner`) → 초상 옆에 짧게 두 줄**(달성률 패널과 같은 PartsEngine 텍스트 방식).

### 기준과 자리
- 기준 = current.json 최신 실행본(r19 설치 뒤). 시작·끝·마무리 확인, 바뀌면 자동 재기준. 산출물 `ingame/r20_calendar/`. 계약은 빌드 시점 required_*.json 전부 + no-restore 문장.
- 주소 유지 함수(r18 목록 + KR_T18RunSandboxed) 재정의 금지. 원본 함수 이전 0, PACT·EX·FNL 무변경, **세이브 구조 변경 0**(새 전역·구조체 필드 금지 — 횟수를 우리가 새로 세지 않는다). 같은 길이 CALLFUNC 교체만.

### 1. 셈의 출처 (게임이 이미 가진 것만)
- **특훈 횟수**: `C_Ability.training`(`GetTraining`)이 횟수인지 점수인지 `C_TrainingStatusProgress@IncreaseAtSaturday/IncreaseAtWeekday_2`·`L_BattleIncome::Settle`(income nTraining) 을 읽어 판정. 횟수가 아니면 특훈 뒤 대화 풀의 소비 상태(`L_RandomScenario::m_nTableAfterTraining`·`GetAfterTraining(nPartner)`·`PrepareAfterTraining`)로 「그 인물과의 특훈 뒤 대화를 본 수」를 횟수 대신 쓰고 문구를 「특훈 뒤 대화 n번 봄」으로 바꾼다. 어느 쪽인지 인계에 근거와 함께.
- **던전 동행 횟수**: 게임이 인물별로 세는 값이 있는지(`L_Party`·`L_BattleIncome`·`C_Ability`·`L_DungeonInfo`) 확인. 없으면 횟수는 빼고 남은 장면만 보여 준다(문구 「동행 횟수는 게임이 세지 않음」은 화면에 쓰지 않는다 — 그냥 생략).
- **남은 이벤트**: 달력의 표(r19 이름·풀 배정)와 `IsRegisteredEvent`(이 저장)로 센다. 특훈: 그 인물의 **이번 달** 특훈 뒤 대화·우선 대화·특훈 권유 중 안 본 수(달이 바뀌면 값이 바뀜 — 문구에 「이달」). 던전: 그 인물이 person 또는 person2 인 던전 동행 장면 중 안 본 수, **상대별**로(「마코토와 3 · 신카이 2 · 모모세 1」, 0 인 상대는 생략). 회차 기준은 r18 잠금과 같은 「이 저장」.

### 2. 던전 멤버 고르기 — 상태 창 「이벤트」 쪽
- `C_HomeStatusView` 의 쪽 넘김(NowPage/NextPage/PrevPage/MaxPage, `IsShowFeelingPage`)에 쪽 하나를 더한다: 제목 「이벤트」. 줄: 「특훈 n회」(또는 대체 문구), 「이달 남은 특훈 뒤 대화 m」, 「던전 동행 남은 장면」 + 상대별 줄 최대 7줄(「마코토와 3」…), 마지막에 「달력에서 자세히」 안내(글자만, 버튼 아님). 기존 쪽의 파츠·좌표·글꼴을 그대로 쓰고(`CreateNonItemParts`·`SetInfo` 방식), 기존 쪽의 내용·순서는 바꾸지 않는다.
- 상태 창은 본거지 밖(던전 안 멤버 교체 등)에서도 쓰이면 거기서도 같은 쪽이 보인다 — 어디서 열리는지 호출자를 세어 인계에.

### 3. 특훈 상대 고르기 — 초상 옆 두 줄
- `RunSelectPartner` 가 초상(`C_SelectAlly`)을 놓을 때 인물마다 초상 아래(또는 옆, 겹치지 않는 자리) 텍스트 파츠 두 줄: 1줄 「특훈 n회」(대체 문구 가능), 2줄 「남은 대화 m」. 짚은 인물(`activeCharaNo`)은 밝게, 나머지는 흐리게(달성률 패널의 색 규칙). 화면을 나가면 파츠를 지운다(파츠 누수 0 — 두 번 들어갔다 나와도 파츠 수 동일).
- 자리·크기는 원본 파츠 배치(`C_SceneTrainingView`)를 읽어 정하고 탐침 스크린숏으로 겹침이 없음을 확인.

### 검증·탐침
- VM: 두 화면의 셈이 달력 요약 쪽과 일치(같은 저장에서 남은 수 합이 맞음), 달이 바뀌면 「이달」 값이 바뀜, 특훈 횟수 출처 판정 기록. 결함 심기: 남은 수 하나 틀림, 파츠 누수, 짚은 인물 강조 누락, 상대별 줄 0 생략 안 됨 — selftest 에 4종 추가.
- 네이티브 탐침(음소거 사본): 던전 멤버 고르기 → 상태 창 「이벤트」 쪽 스크린숏(인물 2명), 특훈 상대 고르기 스크린숏(짚은 인물 바꿔 2장), 화면 나갔다 다시 들어가기(파츠 수 동일), 본거지 복귀 픽셀 동일. `--verify` PASS, **설치는 하지 않는다.**
