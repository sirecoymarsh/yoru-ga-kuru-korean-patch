### 1.3 줄 나눔 — 이 기능의 가장 큰 제약

**엔진은 줄을 다시 나누지 않는다.** MSG1 항목 하나가 화면 한 줄이다. 근거 셋:

1. MSG1 100,944개 안에 줄바꿈 문자가 **하나도 없다**(덤프에 역슬래시 0바이트).
2. `Ａ＿バックログ登録`(FUNC 3417)은 글에 줄바꿈이 들어 있으면 **오류를 낸다**(`改行コードを含む文字列が登録されました【%s】`).
3. Codex 의 줄 재배치(`page_lineflow_v2`)는 한 「쪽」(CODE 에서 `0x59 <mid> 0x30 <func>` 로 이어 붙은 MSG1 묶음)의 낱말을 **항목 사이로 옮겨 담는** 작업이다. 12,650쪽 28,108줄.

따라서 **치환은 줄 나눔보다 뒤다** — 정확히는 줄 나눔이 빌드 때 이미 끝났고, 런타임 치환이 그 결과를 사후에 늘리거나 줄인다. 길어지면 그 줄이 창 밖으로 나간다.

## 3. 키 표식

### 3.1 글꼴 안에 빈 코드는 없다

- 프록시 표(`fnl_proxy_map_wansung2350.json`)는 **2,368자**이고, SJIS 선두바이트 **9D·9E·9F·E0~EA**(제2수준 한자 영역)만 차지한다.
- 그 2,368자 가운데 대사·시스템 문자열 어디에도 안 쓰인 글자는 **0개**다. 숨길 코드가 없다.
- 반대로 `【 】 「 」 … ・ 　` 는 프록시 표에 없는데 대사에서 34,000번씩 쓰인다 — **원작 글꼴의 글자가 그대로 살아 있다는 뜻**이다.
- 후보 괄호 `〔〕〈〉《》〘〙« »` 는 대사·시스템 문자열에서 **0회**다. 즉 겹치지 않는다.

### 3.2 원문 한자를 키로 쓸 수 있나 — 가설

- 여덟 용어의 일본어 원문(`光狩 火者 火群 チロ 狭間 凍夜 真月 真夜`)은 **한국어 실행본에 0회** 나온다.
- 그 글자들은 **프록시 표가 덮어쓴 영역 밖**이다(어느 것도 프록시 글자가 아니다) — 글립이 남아 있어야 맞다.
- 글꼴 파일 크기: 원본 258,902,794 → 한국어 306,465,937 바이트(**+47.5 MB**). 헤더(`FNA\0`)와 면 표의 앞부분이 원본과 같다. **덮어쓴 게 아니라 더했다**는 정황.
- 프록시 표의 `donor = {"character":"国","index":2494,"validated_face_count":93}` — 특정 칸만 골라 바꾼 흔적.
- **다만 한국어 실행본 대사에 한자·가나가 0자라, 「지금 이 빌드에서 한자 글립이 실제로 그려진다」는 증거는 없다.** 이건 가설이다. 화면으로 확인해야 한다.

### 3.3 표식이 안 보이려면

표식은 **언제나 짝이 등록되어 있으면** 화면에 뜨지 않는다. `ReplaceText` 가 무조건 지나가며 통째로 먹어 치우기 때문이다. 짝 등록이 빠지는 자리가 있으면 그대로 드러난다 — 등록 지점은 4절에.

### 3.5 절대 건드리면 안 되는 문자열

- **STR0 `0x00002cb5`** 는 **글꼴 글자표**다(한글 낱자 1,751자를 나열한 한 줄). 그 안에 「틈」 한 글자가 들어 있다. 시스템 문자열까지 일괄 치환하면 **글자표가 깨진다.**
- EX `顔CG変換テーブル.cgName` 은 `顔／チロ／通常` 같은 **자산 경로**다(일본어 그대로, 번역 안 됨). 한국어 키와 겹치지 않으므로 안전하지만, 경로가 바뀌면 그림을 못 찾으므로 게이트로 막아야 한다.
- **「틈새」는 狭間 의 번역이 아니다.** 대사에 나오는 15건은 전부 `隙間`·`すきま`·`間` 이다(「입술 틈새로」=`唇のすきまから`). 「하자마 → 틈새」를 고르면 **그 15건과 화면에서 섞인다.**

### 5.1 앞선 보고를 정정한다

2026-09-22 4차 보고에서 **「기준 스냅숏에 Codex 모드 탭 배선이 없다. `KR_Flag`·`KR_Poke` 가 속이 빈 함수다」라고 적은 것은 틀렸다.** 원인은 `ain edit --jam` 함정이다 — 고친 함수를 CODE 끝에 새로 붙이고 **옛 바이트를 그 자리에 남기므로** 같은 `FUNC` 가 두 벌 나온다. 앞엣것(JAF 선언 단계가 만든 빈 껍데기)을 읽었다.

	IFNZ 0x948c1e

	CALLFUNC SystemFlagManager::Get
	RETURN
0x948c1e:
	PUSH 0
	RETURN
ENDFUNC KR_Flag
```

```
FUNC 31837                      ; void KR_Poke(int slot, int value)

	.GLOBALREF g_sysFlagList
	.LOCALREF slot
	.LOCALREF value
	X_ASSIGN 1

## 8. 권장안

**안 A(민낯 낱말 키) + 앞 글자 한글 금지 규칙 + 이미 있는 조사 해결기 확장 + 모드 탭은 계약으로 넘기고 회상 화면 메뉴로 먼저 확인.**

까닭:

1. **MSG1 을 건드리지 않는다.** Codex 의 lineflow·polish 스냅숏이 이 프로젝트에서 가장 비싸고 가장 자주 충돌하는 자산이다. 안 A 는 0줄을 고친다.

3. **오탐이 실측으로 20건뿐이고, 규칙 하나로 전부 걸러진다.** 걸러 낸 결과가 원문 개수와 맞아떨어진다(토야 61=61).

## 9. 사용자에게 물을 것

1. **긴 후보를 살릴 것인가.** 「얼어붙은 밤」(+120px)은 12줄이 창 밖으로 나간다. ① 그 12줄만 줄을 다시 나눈다(MSG1 을 건드린다) ② 짧은 후보로 바꾼다(예: 「언 밤」 +48px) ③ 그 항목만 뺀다 — 셋 중 무엇인가.
2. **「진월/참된 달」처럼 +48px 인 후보를 허용할 것인가.** 한계폭에 딱 붙는 줄이 32줄 생긴다. 안전폭은 넘지만 잘리지는 않는다.
3. **「호무라」를 목록에서 뺄 것인가.** 대사 등장 4건, 예외 3건. 위 8절 표 참고.
4. **「하자마 → 틈새」를 고를 수 있는가.** 대사에 이미 「틈새」가 15건 있고 **전부 다른 낱말**(`隙間`·`すきま`)이다. 화면에서 섞인다. 다른 후보(예: 「틈」)로 바꿀 것인가.
