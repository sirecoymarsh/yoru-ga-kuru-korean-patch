## 4. 구조 추출 규칙 (Phase 1)

### 4.1 장면 단위
- **이벤트 함수 하나 = 카드 하나.** id 는 `E%05d` 숫자 그대로(`10001`). 이름표시는 나중에 붙인다.
- 한 이벤트가 다른 이벤트 함수를 직접 `CALLFUNC` 하면 "사슬"(edge kind `calls`)로 적고 카드는 따로 둔다. 시스템 이벤트(`ＳＹＳＥＶ`)·튜토리얼은 카드가 아니라 `system` 항목이다.
- E5xxxx(회상 재생본)는 카드로 두되 `replay_of: <needEvNo>` 를 달고, 본편과 대사가 **글자 단위로 같은지** 비교해 `text_identical: true/false` 와 다른 줄 수를 적는다. 검수 중복 제거의 근거다.

### 4.3 뽑는 순서
1. 원본 AIN 에서 `-f`, `-g`, `-S`, `-s`, `-m`, `-t` 덤프와, **이벤트 함수 1,162개 + 2.4 절 클래스 전 메서드 + `■`/`●` 도우미 전부**의 jam 을 `--function` 으로 받아 둔다(파이썬 subprocess, 병렬 가능). 해시를 `graph\inputs.json` 에 남긴다.
2. 도우미 함수 jam 을 먼저 읽어 **각 도우미가 무엇을 쓰는지**(어느 전역·어느 플래그 배열·인수 뜻)를 `engine\helpers.json` 으로 만든다. 예: `■親密度上昇いずみ１` 이 `L_Party`/`LAbility` 의 어느 값을 얼마나 올리나, `■汎用フラグ／設定` 의 인수가 번호·값인지.
3. 이벤트 함수 jam 을 파싱한다: `MSG` 범위, `CALLFUNC` 목록, `PUSH` 인수 복원(스택 모사: `PUSH a; PUSH b; CALLFUNC f` → f(a,b)), `IFZ/IFNZ/JUMP` 로 감싸인 블록 → 4.5 의 `lines.jsonl` 조건.
4. 스케줄러(`L_EventCall::*`, `L_RandomScenario::*`, 날짜 표 소비자, `C_TestStart`)를 읽어 **트리거**를 채운다. `nTable` 을 채우는 코드(어디서 `TMap<int,int>` 에 넣나)가 날짜→이벤트 표의 실체다.
5. 결말: `E6xxxx` 30개 + `MAKOTO_ENDING` + `IsFinishLastChapterEffect` + `GameExecLastChapter` + `■ムービーＥＤ` 호출 위치로 결말 이벤트와 진입 조건을 잡는다.
6. 회상: `回想` 표와 `■閲覧／…登録` 호출을 대응시킨다.

### 4.4 검사기 `checks\schedule_check.py` (route_check.py 대체)
- 구조 문제: 트리거 없는 이벤트(`unknown`), 존재하지 않는 이벤트를 요구·등록·호출, 순환 사슬, 풀에 있는데 함수가 없는 번호, 함수는 있는데 표·스케줄러·풀·회상·사슬 어디에도 안 나오는 번호(→ `unresolved`).
- **도달 시뮬레이션**: 달력을 4/9 부터 끝까지 돌리며 정책(매주 특훈 상대 = 인물 X 고정, 초대 수락/거절, 선택지 답 조합)별로 어떤 이벤트가 어느 날 발화하는지 계산한다. 정책 집합: 인물 7명 × {항상 수락, 항상 거절} × 선택지 답 전수(21개 이벤트, 답 2~3개 → 조합은 이벤트별 국소 처리). 출력 `checks\reach.csv`(이벤트 × 정책 → 첫 발화 날짜 또는 미도달).
- 결말 판정: 정책마다 마지막에 어느 결말 이벤트에 닿는지. **인물별 루트 규칙(최고 친밀도)과 항목별로 맞아야 한다.**
- `--selftest`: 트리거 하나를 틀리게 바꾼 사본에서 대조가 실패하는지 증명한다.

### 4.5 조건 태그 대사 `graph\lines.jsonl`
```json
{"event": 10001, "m": 61443, "conditions": []}
{"event": 10001, "m": 61470, "conditions": ["choice:12345==2"]}
{"event": 10001, "m": 61501, "conditions": ["general_flag:12==1", "affection:2>=3"]}
```
- 추출 텍스트에는 분기 변형이 전부 이어 붙어 있다. 요약·시작 대사·"이 이벤트를 읽었다" 판정 모두 이 파일을 거친다(스킬 `structure-extraction.md` 6절과 메모리 [[vn-summary-must-respect-branch-variants]]).
- 블록 경계가 ±1줄 틀릴 수 있다. 경계 줄에 기대는 주장은 쓰지 않는다.

## 6. 차트 설계 (추천안; 미결은 11절)

### 6.1 모양 — 달력 격자
- 가로: 4월 … 11월(+ "최종장/결말" 열). 월 안은 날짜순.
- 세로 범주(위→아래): 본편(E0 본편 트리거) / 이즈미 / 교카 / 마코토미 / 마코토 / 신카이 / 호시카와 / 모모세 / 던전(첫 동행·걷기) / 결말. 인물 한국어 표기는 용어집·화자명 정본을 그대로 쓴다(추측 금지).
- 풀(특훈 후 대화, 초대 대사)은 (인물, 월) 하나에 **묶음 카드** 하나. 펼치면 원소 목록(번호·읽음 여부·첫 줄).
- 선은 `chains_to`·`registers_events`·`requires_events` 에만. 친밀도 조건은 카드 안 배지("친밀도 3 이상").
- 21개 선택지 이벤트는 카드 아래 작은 가지(답 문구 + 갈리는 줄 수). 답 문구는 설치된 번역에서 인용, 새로 번역하지 않는다.
- 카드에 항상 보이는 것: 번호, 범주, 날짜/조건 배지, **읽음 표시**, 대사 줄 수, 회상 재생본이면 "재생본(본편 X 와 동일/다름 n줄)".
- 검수용 기능(첫째 목적): "안 읽은 이벤트만 보기", "가장 적은 이동으로 다 보는 순서"(같은 날짜·같은 문맥끼리 묶은 방문 순서 목록 `chart\visit_order.md`), 이벤트 번호 검색, 인물·월 필터.

### 6.2 스포일러 층위 (도화이담 추천안을 좁게 옮김)
| 층 | 무엇 | 언제 |
|---|---|---|
| 늘 보임 | 범주·월·카드 개수·번호·읽음 표시·줄 수·선택지 **문구** | 항상 |
| 읽으면 열림 | 카드 제목·시작 대사(앞 세 문장, 조건 줄 제외)·요약 | 그 이벤트를 읽었을 때(`LEventFlag` Once 또는 Total) |
| 조건 | 트리거 조건·친밀도 배지·사슬 선 | 그 카드를 읽었을 때 |
| 결말 조건 | 결말 카드 아래 진입 조건 | 그 결말을 읽었을 때 |
| 전체 보기 | 전부 | 경고 뒤, 이번 실행에서만 |

- 미개방 카드는 "미개방"만. 이동도 막는다. **잠길 자료는 접근자 하나로만 읽는다**(HTML 이라도 함수 하나로 통일하고, 가짜 진행 상태로 렌더해 누출 0 을 단언).
- 제목·요약·시작 대사는 Phase 1 의 **뒷부분**이다. 먼저 번호·구조만으로 차트를 완성하고, 내용은 `lines.jsonl` 기준으로 `check_summaries.py` 게이트를 통과한 것만 넣는다. 회상 장면은 기존 한국어 캡션을 제목으로 쓴다.

### 6.3 화면 문구
- 쉬운 한국어. 결말은 좋은·보통·나쁜 같은 뜻말, 갈림은 번호 대신 뜻(단, 결말 이름은 사용자가 정한다 — 11절 D6). 게임 UI 어휘(특훈·초대·던전·회상)는 설치된 번역과 같게. 번역 쪽 용어가 바뀌면 차트도 따라간다.

### 6.4 HTML 판(Phase 1 산출)
- 단독 파일 `chart\yoru_flowchart.html`(외부 스크립트 없음, 파일 열기만으로 동작). 자료는 파일 안에 JSON 으로 굽되 **생성기**(`chart\build_chart.py`)가 `schedule.json` 에서 만든다 — 손으로 고치지 않는다.
- 진행 상태: `progress.json`(8절 형식)을 끌어다 놓거나 파일 선택으로 읽는다. 없으면 "아무것도 안 읽음" 상태(전부 잠김) — 이게 기본 렌더다.
- 다크 기본. 그림은 넣지 않는다(Phase 1). 배율 100~150%, 창 높이 630px 에서 머리글이 안 겹치고 격자가 가로 스크롤로만 움직이는지 렌더 게이트(헤드리스 브라우저나 스크린샷 비교로 확인; 브라우저가 없으면 DOM 치수 계산으로 대신하고 그렇게 적는다).

## 7. 이동 (Phase 2) — 엔진 자기 경로

### 7.1 원칙
- 스크립트 밖에서 VM 메모리를 만지지 않는다. **AIN 안의 함수**(원작 실행기 또는 KR_ 함수)가 원작 스케줄러와 같은 호출 경로로 이벤트를 띄운다.
- 이동 전 상태 만들기(날짜·파티·친밀도·플래그)는 원작 실행기가 하는 그대로만 한다. 실행기가 안 하는 걸 우리가 억지로 맞추지 않는다. "그 문맥에선 못 간다"는 이유를 보여 준다.
- 이동은 UI 에서 **요청만 쌓고**, 게임 루프의 안전한 지점(원작 실행기가 실행되는 같은 지점)에서 소비한다. Codex 의 소탕 설계 DEC-006(잠금 → 계획 → 검증 → 반영)과 같은 꼴.
- 이동으로 생긴 상태(친밀도 상승·이벤트 Once 기록·회상 등록)는 **원작 실행기가 남기는 것과 같게** 둔다. 검수용 이동이 세이브를 더럽히는 게 걱정되면 "검수 모드" 슬롯을 따로 쓰라고 안내한다(사용자 세이브를 자동으로 백업·수정하지 않는다).

### 7.2 후보 순서(Phase 0 결과로 확정)
1. **원작 실행기 노출**: 모드 탭에 "장면 실행" 버튼 → `C_TestScenario` 화면(`menu::detail::CTestMenu*`)을 그대로 띄운다. 한국어 라벨과 읽음 표시(`LEventFlag::GetOnce/GetTotal`)를 덧붙인다. 가장 적은 코드, 가장 원작다움.
2. **KR_ 이동 함수**: 실행기가 릴리스에서 죽어 있거나 문맥 세팅이 부족하면, `C_TestScenario@Run*` 이 하는 준비를 옮겨 적은 `KR_RunEvent(no)` 를 만들고 `LSys3xScript::RunEvent`(또는 `L_EventCall::Call`)로 부른다. 준비 코드는 실행기 jam 을 **베끼되** 새 규칙을 넣지 않는다.
3. 게임 안 격자 페이지(D1 이 "게임 안"일 때만): PACT 새 페이지 + 동적 텍스트/사각형 부품. Codex 의 `build_mod_tab_20260915.py` 방식.

### 7.3 금지
- 세이브 파일 직접 편집, 날짜 직접 증가(`C_GameDate@NextDay` 강제 호출), 플래그 일괄 완료, 회상 강제 개방.
- 현재 실행본 `runtime\` 에 쓰기. 후보는 `ingame\candidate\` 에만. 설치는 사용자·Codex.

## 10. 금지·주의 (반드시)

1. **실행 폴더·세이브 폴더에 쓰지 않는다. 게임을 실행하지 않는다.** Codex 세션이 같은 실행본을 오늘도 고치고 있다(메모리 [[concurrent-agents-branch-divergence]]). 시험 사본이 필요하면 폴더를 통째로 복사하되 그것도 사용자 지시 뒤에.
2. 스포일러: 사용자는 이 게임을 실플레이 중이다(세이브 09-15~09-22). **최종 보고·채팅에 줄거리·인물 정체·결말 내용을 쓰지 않는다.** 이벤트 제목·요약·시작 대사가 든 파일은 맨 위에 경고 줄을 달고 `chart\spoiler\` 아래에만 둔다. 번호·범주·조건·줄 수는 스포일러가 아니다.
3. 도우미 함수의 뜻은 jam 으로 확인한다. 이름만 보고 단정하지 않는다(`C_GameEventManager` 는 이름과 달리 던전 마커 관리자다).
4. 합계 대조 금지. 항목별로.
5. 게이트를 만들면 결함을 심어 실패를 본다. 0 아닌 검출 수는 증거가 아니다([[gate-nonzero-hits-are-not-proof]]).
6. 파이썬 `PYTHONUTF8=1`; `alice.exe` 는 subprocess; Git Bash heredoc 은 역슬래시를 줄인다 — 파일은 Write 로. PowerShell `.ps1` 안 한글 경로 금지.
7. 파일 링크는 `P:\AI` 기준 상대 경로(`Codex/projects/YoruGaKuru_flowchart_20260922/…`).
8. 화면 문구는 쉬운 한국어; 인물·용어 표기는 용어집 그대로; 새 번역·새 용어를 만들지 않는다.
9. 가설은 가설이라고 쓴다. 확인한 것과 섞지 않는다.
10. 사용자에게 물을 게 생기면 멈추지 말고 추천안으로 진행하고 11절 표에 "물을 것"으로 적는다.

### 범위
1. Phase 0 전부(2.8 의 (a)~(d), 2.4 의 가설 확정·기각, 4.3-2 도우미 사전) → `engine\엔진메모.md`.
