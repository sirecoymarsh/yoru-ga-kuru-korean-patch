## 1. 갈래 A 가 정말 독립인가

`checks/_common.py` 는 추출기(`scratch/extract.py`·`exparse.py`·`jamindex.py`)를 **쓰지 않는다**.
`ex.x` 와 `code.jam` 원문을 자기 정규식으로 다시 읽는다(남의 파서를 쓰면 그 맹점까지 물려받는다).

그 덕에 실제로 세 가지 결함이 걸렸고 고쳤다.

| 갈래 A 가 잡은 것 | 원인 | 고침 |
|---|---|---|
| 회상 재생본 43개의 `person` 이 비어 있다 | 추출기가 타입 201~204 에 인물을 안 붙였다 | 타입→인물 규칙 보완 |
| `ConditionalCall` 13행 중 4행이 인수와 다르다 | 친밀도 조건이 없을 때(`feeling=-1`) 인물 번호를 버렸다 | 원인수 9개를 `raw_args` 로 그대로 보관 |
| `L_EventCall::D1101` 이 부르는 이벤트 4개에 트리거가 없다 | 인수가 지역변수라 상수 훑개에 안 걸렸다 | 특수 함수는 `.LOCALASSIGN` 까지 따라가게 보완 |

덤으로 **두 갈래가 독립으로 같은 값을 준** 것도 적어 둔다.

| 항목 | 갈래 A | 갈래 B |
|---|---|---|
| 선택지 있는 이벤트 | EX 표 `選択肢あり=1` 21행 | jam 에서 분기 있는 이벤트 21개 (**목록까지 같다**) |
| 음성 있는 이벤트 | EX 표 `音声あり=1` 133행 | jam 에서 `VOICE` 를 부르는 이벤트 133개 |
| `Check` 무조건/조건 규칙 | 원본 jam 정규식 81 / 13 | 유사코드 파서 81 / 13 (인수까지 일치) |
| 달력 길이 | EX `日付テスト実行データ` 223행 | 4/9(주1) → 11/17 을 하루씩 세면 223일, 끝 요일 6 = `SetDate(11,17,6)` |
| 특훈 유혹 이벤트 번호 | EX `特訓誘い<인물>` | `C_SceneTraining@PlaySelPartnerAction` 의 상수 배열 (7×1 + 7×5) |
| jam 함수 자르기 | `alice ain dump --function` 8개 | 내 색인 — 줄 단위로 완전 일치 |

사슬 그래프 **전체**(1,164장 모두를 부모·자식으로)에서 진입차수 2 이상을 세야 13이 된다.
차트가 「공유」로 표시하는 것은 **묶음 안에서 부모가 둘 이상인 단계 9개**다(화면에 필요한 값이라서).
두 값 모두 `graph/groups.json` 의 `counts` 에 있다.

### 선택지 답 문구

답 문구는 메시지가 아니라 **문자열 표**에 있어 번역 지도(m → 한국어)에 없다.
실행본 AIN 의 문자열 표를 읽기 전용으로 덤프해 같은 색인에서 가져오고 FNL 프록시 글자를 되돌렸다.
색인이 밀리지 않았다는 근거: ASCII 전용 문자열 7,357개가 원본과 **글자까지 같다**(다른 것은 `AUTO` 하나,
Codex 가 UI 로 번역한 것). 답 문구 한국어를 못 찾은 것 **0건**.

### 던전 단계 차례

클래스 jam 의 **(메서드 함수 번호, 메서드 안 줄 번호)** 순으로 정했다. 메서드 이름(Entrance/Exit/B/R)의
뜻은 쓰지 않았다 — 추정이 끼면 안 되기 때문이다. 22자리의 근거를 `graph/groups.json` 의
`dungeon_order_evidence` 에 이벤트마다 `{event, method, func_no, line}` 으로 남겼고,
표는 `engine/엔진메모.md` 11절에 있다.

## 5. 배치 (브라우저 실측)

라벨과 묶음층이 들어가 카드 높이가 달라졌으므로 **묶음 35개를 전부 펼친 채로 다시 쟀다**.

| 창 크기 | 쪽 세로 | 쪽 가로 | 머리↔경고 | 경고↔격자 | 격자↔바닥 | 달 머리줄 겹침 | 격자 가로 스크롤 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 1280×630 (배율 100%) | 0 | 0 | 0 | 0 | 0 | 0 | 735px |
| 1024×504 (≈125%) | 0 | 0 | 0 | 0 | 0 | 0 | 991px |
| 853×420 (≈150%) | 0 | 0 | 0 | 0 | 0 | 0 | 766px |
| 1280×580 | 0 | 0 | 0 | 0 | 0 | 0 | 735px |
| 1280×900 | 0 | 0 | 0 | 0 | 0 | 0 | 735px |

- 쪽 자체는 어느 크기·어느 펼침 상태에서도 스크롤하지 않는다. 격자만 안에서 움직인다.

- 쪽 자체는 어느 크기에서도 스크롤하지 않는다. 격자만 안에서 움직인다.
- **격자 안의 세로 스크롤은 남는다**(카드 1,164장). 설계도 9절의 「세로 스크롤 없음」은
  쪽 기준으로 읽어 통과로 본다. 카드를 한 화면에 다 넣을 방법은 없다.
- 측정은 미리보기 창에서 `getBoundingClientRect` 로 실측했다. 되풀이 가능한 게이트(`stage.py`)는
  같은 성질을 **정적으로** 검사한다(세로 flex·sticky 머리줄·칸 최소 폭).
- 2차 작업에서는 작업 폴더가 바뀌어 `file://` 로 못 열게 됐다. `python -m http.server` 를
  **읽기 전용으로** 띄워 `http://127.0.0.1:8787/` 로 재어 보고 바로 껐다.

## 6. 남은 위험

1. `system IsDebugMode` 의 실제 값은 스크립트에서 확인할 수 없다(가설).
2. 친밀도 모형은 일요일 남은시간에 달려 있다(2.5).
3. E6xxxx 30개가 본편에 안 나온다는 것은 「부르는 자리를 못 찾았다」에 근거한 가설이다.
4. 회상 메뉴 번호(201~207)와 EX 페이지(1~7)의 대응은 행 수로 맞춘 가설이다.
5. 화면에서 실제로 그렇게 보이는지는 **사용자 확인 전이다**. 로그·해시는 화면 증거가 아니다.
