# 밤이 온다! 오토 내비게이션 모드 — 설계 초안 (2026-10-15, Claude Opus 5.5)

> ⚠ **스포일러 경고.** 3절부터는 루트가 정해지는 조건, 선택지마다 열리는 장면, 결말 쪽 분기가 들어 있다.
> 사용자는 이 작품을 플레이하는 중이다. 채팅에는 이 문서의 3~4절 내용을 옮기지 않는다.

## 1. 요청

사용자(10-15): 「특정 루트를 선택하면 자동으로 모든 선택지가 사라지고 그냥 클릭만 해도 해당 인물의 선택지쪽으로 진행되는거」

첫 질문(범위·켜는 곳)에 대한 사용자 답(10-15):
- 범위: 「특훈은 능력치 관계때문에 대상과만 갈수는 없어. 좋은 방법이 없을까?」
- 켜는 곳·동작: 「게임 시작시 선택하고 창위 말고 옵션의 모드 메뉴에서 자유롭게 교체 가능 정확한 기능은 호감도 선택지가 표시되고 20초후 자동으로 선택되게」

## 2. 사양

### 2.1 사용자가 정한 것

- 새 게임을 시작할 때 고른다(이즈미·쿄카·마나미·마코토·쓰지 않음).
- 옵션 화면의 「모드」 탭(Codex 의 PACT 185쪽)에서 언제든 바꾼다. 게임 창 위 메뉴바는 쓰지 않는다.
- 선택지는 **사라지지 않는다.** 창은 그대로 뜨고 고른 인물 쪽 답이 표시되며, 20초 동안 안 고르면 그 답이 자동으로 골라진다. (내 해석: 그 사이 다른 답을 직접 골라도 된다 — 확인 요청함)
- 특훈 상대를 매주 대상으로 고정하지 않는다(능력치 때문에).

### 2.2 내가 낸 안 (사용자 확인 대기)

- **특훈:** 대상 인물의 「특훈 뒤 이야기」(우선 대화)가 기다리는 토요일에만 특훈 상대 화면에서 대상에 ★ 표시 + 20초 뒤 자동 선택. 판정은 `L_RandomScenario::GetAfterTrainingEvent(대상) > 0` — 게임이 토요일 아침 초대(5011~5014)를 띄울 때 쓰는 판정과 같다. 그 밖의 토요일은 표시·자동 없음. 인물별 우선 대화 수는 이즈미 7·쿄카 4·마나미 4·마코토 8(10월 것 다수는 루트 뒤 대화).
- **친밀도 보정(루트 보장):** 특훈·던전 동행을 자유롭게 두면 친밀도가 모자랄 수 있으니, 대상의 친밀도가 그날 필요한 값(대상 장면의 친밀도 조건, 10/11 의 50, 10/15 의 60 + 다른 세 명보다 1 높게)에 못 미칠 때만 그만큼 채운다.
- **표시 규칙:** ★ 는 「20초 뒤 자동으로 골라질 답」. 대상과 관계있는 선택지는 대상 쪽 답, 관계없는 선택지는 다른 인물 친밀도를 올리지 않는 답(그것도 같으면 1번).
- **던전 동행:** 건드리지 않는다.
- **저장:** 세이브마다(3.8). 타이틀에서 연 옵션에서는 바꿀 수 없게(게임 중에만).

채팅에서 사용자에게 한 설명은 「루트는 친밀도로 정해지고, 친밀도는 대부분 토요일 특훈 상대와 던전 동행에서 쌓인다」와 「특훈 뒤 이야기가 있는 토요일」까지다. 날짜·문턱·선행 장면은 말하지 않았다.

## 3. 엔진 사실 (스포일러)

### 3.1 대사 선택지

- 선택지가 있는 이벤트 함수는 21개다(본편 12 + 특훈 뒤 우선 대화 7 + 회상 재생본 2). EX `シナリオテストデータ` 의 `選択肢あり=1` 21행과 같다.
- 함수는 `■選択メッセージ／選択肢追加(번호, 글, "")` 로 답을 쌓고 `■選択メッセージ／実行(0, 200)` 의 반환값을 번호와 비교해 `g_EvResult`(다음 이벤트 번호)만 정한다. 분기 뒤 대사는 함수 안에 없다.
- 호출 꼴(E00611 에서 확인):
  `PUSHLOCALPAGE / PUSH 0 / PUSH 0 / PUSH 200 / CALLFUNC ■選択メッセージ／実行 / X_ASSIGN 1 / POP` → `res == 1 → 612`, `== 2 → 613`, `== 3 → 614`, 나머지 → 615.
- `■選択メッセージ／実行`(FUNC 27941) 본문: 디버그 점프 무시면 `g_SelectMessage`(전역 269)를 지우고 -1, 없으면 -1, 있으면 `C_SelectMessage@Run(bキャンセル, n時間, 0)` 결과를 돌려주고 지운다. 지우기만 하는 함수가 `■選択メッセージ／初期化`(FUNC 27942)다.

## 5. 구현안 (2.2 가 확정되면 이대로)

### 5.1 선택지 — 표시 + 20초 자동

- 19곳 호출의 `CALLFUNC ■選択メッセージ／実行` 피연산자를 같은 길이로 자리별 함수 `KR_AN_E00058` 따위(서명 `int (bool, int)`)로 바꾼다. 자리별 함수는 `KR_ANSelect(이벤트 번호, bキャンセル, n時間)` 하나를 부른다.
- `KR_ANSelect`: 꺼져 있거나(3.8 이름 없음) 재생 중(회상·달력 재생·차트 재생)이거나 표에 없으면 원래 `■選択メッセージ／実行` 그대로. 켜져 있으면 표에서 고를 번호를 찾아 `g_SelectMessage.m_SelectInfos` 의 그 항목 Text 앞에 ★ 를 붙이고, 대기 표식(고를 번호·시작 시각)을 세션 변수에 둔 뒤 원래 `■選択メッセージ／実行` 을 부르고, 돌아오면 표식을 지운다.
- `C_SelectMessage@Run` 안의 `CALLFUNC AFL_Parts_WaitForClick` 를 같은 길이로 `KR_ANWait(delegate, bool)` 로 바꾼다. 표식이 없으면 원래 함수 그대로. 있으면 전역 함수 `KR_ANTick` 대리자로 기다린다: 매 프레임 `g_SelectMessage` 의 원래 `Update` 를 부르고, 20초가 지나면 `AFL_Parts_EndWaitForClick(고를 번호)`.
- 자리별 함수를 쓰는 까닭: 실행 중에 부른 이벤트 이름을 알아내는 길(`system GetFuncStackName`)은 재생 샌드박스 안에서 깊이가 달라질 수 있다. 번호가 자리마다 박혀 있으면 흔들리지 않는다.
- ★ 글자는 CP932 81 9A(게임 문자열에서 이미 씀, 한글 대체 영역 9D~9F·E0~EA 와 안 겹침).
- 남은 초를 창 제목에 보일지는 구현 때 탐침으로 본다(`m_Title` 이 그려지는지 확인 필요).

### 5.2 특훈 상대 — 이야기가 있는 토요일만

- `RunSelectPartner` 안의 클릭 대기를 같은 길이로 가로챈다. 켜져 있고 `LAbility::CanSelect(대상)` 이고 `L_RandomScenario::GetAfterTrainingEvent(대상) > 0` 이면: 대상 초상 위 r20 두 줄 자리 또는 이름 칸에 ★ 표시, 20초 뒤 대상으로 대기를 끝낸다. 그 사이 다른 사람을 누르면 그대로 따른다.
- 그 밖의 토요일·합류 전·꺼짐은 원래 대기.
- 표시 자리는 r20(`KR_T20*`)·r23 층과 겹치지 않게 구현 때 화면으로 정한다.

### 5.3 친밀도 보정 (2.2 확정 시)

- 하루가 시작될 때(날짜 판정 `L_EventCall::Check` 앞 한 자리) 대상의 화면값이 오늘 필요한 값보다 낮으면 내부값을 그만큼 올린다. 필요한 값 표는 `schedule.json` 의 대상 `feeling_gate`·우선 대화 조건(≥20·≥30)·10/11 의 50·10/15 의 60, 그리고 10/15 에는 다른 세 명의 최고값 + 1. 표는 빌드 때 자료에서 만들어 함수에 상수로 넣는다.
- 낮출 일은 없다. 다른 인물 값은 건드리지 않는다.

### 5.4 켜고 바꾸기

- 새 게임: 새 게임 초기화(`LEventFlag::ClearOnce`) 뒤 첫 장면 전에 `■選択ダイアログ` 로 「누구의 이야기를 따라갈까요?」 — 이즈미 / 쿄카 / 마나미 / 마코토 / 쓰지 않음. 자리는 구현 때 `呼出／オープニング` 앞뒤에서 찾는다.
- 옵션 「모드」 탭: 줄 하나 「오토 내비게이션」 + 체크박스 다섯(쓰지 않음·이즈미·쿄카·마나미·마코토)을 라디오처럼(3.9 선례). 타이틀에서 연 옵션에서는 바꿔도 남지 않으므로 잠그고 「게임 중에만 바꿀 수 있어요」를 보인다(게임 진행 중 판정 자리는 구현 때 확인).
- 저장: 3.8 의 이름 하나.

### 5.5 기준과 계약

## 6. 검증 계획

- 정적: 바꾼 자리 외 바이트 동일, 계약 보존, 엔진 디스패치 검사(쓰지 않는 명령 0).
- 탐침: 선택 이벤트 19곳을 인물 4명 × 켜짐/꺼짐으로 재생 — ★ 가 표의 답에 붙는지, 20초 뒤 그 답이 골라지는지, 20초 안에 다른 답을 고르면 그 답이 되는지, 꺼짐이면 원래 창 그대로인지, 회상·달력 재생에서는 손대지 않는지.
- 특훈: 토요일 저장을 이어 받아 이야기 있는 주/없는 주/합류 전.
- 보정: 날짜를 넘기는 시뮬레이션으로 대상 장면이 다 뜨는지(`checks\simulate.py` 를 보정 규칙으로 돌려 봄).
- 세이브: 옛 세이브는 꺼짐, 켠 세이브를 저장·불러오기 해도 유지, 새 게임 때 초기화.
- 실기 화면 확인은 사용자 몫.
