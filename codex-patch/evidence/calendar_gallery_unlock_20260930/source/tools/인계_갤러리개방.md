# 갤러리 전체 개방 연동 층 KR_G25 — 인계

작성: Claude Opus 5.5 (claude-opus-5-5), 2026-09-30. 설계 발주: Claude Fable. **설치 안 함**(`--check` 까지만 실행).

## 1. 무엇을 하나

메뉴바 「모드 → 전체 개방」(저장 폴더 `YoruKR_Chart.dat` = 1)이 켜져 있으면 게임 자체의 두 갤러리도 모두 열린다.

- **추억 감상**(회상 모드, 76칸): 안 본 장면도 제목이 보이고 재생된다.
- **CG 감상**(60칸, 90장): 모든 칸이 열리고, 칸 안의 모든 CG를 볼 수 있다.
- **음악 감상**: 변경하지 않았다. 이 빌드에서는 두 판정(`C_SceneModeSoundView@IsEnableSound`, `S_SoundModeCellInfo@IsEnable`)이 모두 상수 참이라 원래 전부 열려 있다(아래 4절).

「전체 개방 되돌리기」를 하면 다시 원래 판정(본 것만)으로 돌아간다. 이벤트 캘린더(메뉴바 차트)와 인게임 달력의 읽음 판정·라벨·요약 숨김은 전체 개방과 무관하게 **설치본과 똑같다**.

## 2. 설계와 발주서와 달라진 점

### 2.1 발주서 배치의 문제(고침)

발주서는 플래그를 `N_ModeScene::CheckEnabelScenario` 안에 넣고, 캘린더 보호는 `KR_G25All()` 의 `KR_CActive()` 검사에 맡겼다. 그런데 `KR_CGlobal` 은 **차트 밖에서도 불린다**.

- 인게임 달력의 라벨 getter 사슬(`KR_T19EvShort` / `EvHead` / `EvWhen` → N29 → S29 → R29, 그리고 U29 / TF29 계열)이 `KR_P29Read` → `KR_CGlobal` 을 문맥 검사 없이 부른다. 거기서는 `KR_CActive()` 가 거짓이다.
- 그 결과 발주서 배치대로면, 전체 개방 중 인게임 달력에서 회상과 이어진 151개 이벤트의 읽음 판정이 뒤집힌다.
  - VM 에서 아무것도 안 본 상태로 재면 151개, 무늬 상태로 재면 61개였다.
  - 선택 라벨 15개와 「언제」 칸 17개가 「미열람 장면」 대신 선택지·합류 정보를 보여 준다(스포일러).

**해결:** `KR_CGlobal` 의 `CALLFUNC N_ModeScene::CheckEnabelScenario` 를 같은 길이로 `KR_G25SceneBase` 로 바꿨다. `KR_G25SceneBase` 는 원래 판정 함수를 바이트 그대로 복제한 것이다. 이제 캘린더 코드는 어떤 문맥에서도 플래그가 들어간 판정을 부르지 않는다. `KR_G25All` 의 `KR_CActive()` 검사(발주서 계약)는 그대로 두어 이중 보호로 삼았다.

### 2.2 바이트 길이 정정

- `.GLOBALREF N_ModeScene::DbgEnableAll` 은 10바이트가 아니라 **14바이트**다(`PUSHGLOBALPAGE`(2) + `PUSH 0x134`(6) + `X_REF 1`(6)). 그래서 `PUSH 1; PUSH 0; POP`(6+6+2)으로 바꿨다.
- CG 판정은 HLL 직접 호출(14바이트)이 **아니다**.
  - `UpdateEnableCG` 는 `CALLFUNC Ａ＿ＣＧモード確認`(fid 6145, 6바이트)를 부른다. 그 함수의 몸체가 `PassRegister.ExistText(0, name)` 이다.
  - HLL 의 실제 형태는 `bool PassRegister.ExistText(int nHandle, string pIText)` 이다.
  - 따라서 이 자리는 CALLFUNC 피연산자만 `KR_G25Exist` 로 바꿨다(4바이트).
  - `Ａ＿ＣＧモード確認` 을 부르는 곳은 `UpdateEnableCG` 1곳과 본거지 패널 CG 달성률 `KR_T8CgCount` 90곳이다. `KR_T8CgCount` 는 그대로 두었으므로 달성률은 실제 진행을 계속 보여 준다.

### 2.3 호출자 조사(설치본 코드 전체, FUNC/ENDFUNC 중첩 반영)

- `CheckEnabelScenario` 를 부르는 곳은 3곳이다.
  - `C_SceneModeScene@ExecScene`: 재생
  - `C_SceneModeSceneSelectView@Init`: 선택 화면 목록
  - `KR_CGlobal`
- 발주서가 말한 「SelectView 람다」 호출은 실제로 `SelectView@Init` 본문 안에 있다. 람다 본문 바로 뒤에 놓여 있어 덤프 순서상 람다에 속한 것처럼 보였을 뿐이다.
- `KR_CGlobal` 안의 호출은 1곳이다.

## 3. 바이트 계획(설치본 `abae5787…` → 후보 `fae56fb7…`)

- 결과적으로 `CheckEnabelScenario` 의 첫머리는 `if (KR_G25All() && 1) return true;` 로 동작하고, 그 뒤는 원래 판정(EX `回想.ページN` needEvNo → `E%05d` → `■閲覧／シナリオ登録確認`)이다.
- 스택 효과: A 는 `CALLHLL`(+1) = `CALLFUNC`(+1) `PUSH`(+1) `POP`(-1), B 는 +1 = +1이다.
- 두 창 안으로 떨어지는 점프는 없다(설치본 코드 전체의 점프 대상 확인).
- 옛 CODE 에서 바뀐 바이트는 이 5곳의 19바이트뿐이다.
- STR0 prefix 와 MSG1 은 그대로이고, STR0 에 2행(`YoruKR.G25.All`, 새 안내문)이 추가됐다.

## 4. 음악 감상

- `C_SceneModeSoundView@IsEnableSound`: 바이트 `PUSH 1; IFNZ →(PUSH 1; RETURN)`. 상수 참이다.
- `S_SoundModeCellInfo@IsEnable`: 디버그 경로(`IsDebugMode && N_ModeSound::DbgEnableAll`)를 빼면 역시 `PUSH 1; IFNZ →(PUSH 1; RETURN)` 이다.
- 두 함수 모두 후보에서 바이트가 동일하다. 잠긴 표시 경로는 없어 변경할 것이 없다.

### 5.2 네이티브 탐침 (`probe_gallery_unlock.py` → `evidence/native_probe.json`)

**GALLERY_UNLOCK_NATIVE_PASS**, 21개 검사 모두 통과, 278초.

**실행 조건**
- 격리 무음 사본 `probe/run`: 큰 아카이브는 읽기 전용 하드링크, 저장 폴더는 type 2 개인 폴더, 전역 기록은 r24 사본.
