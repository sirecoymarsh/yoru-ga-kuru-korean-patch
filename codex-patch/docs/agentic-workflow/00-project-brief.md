# 일반 던전 소탕 — 설계서

> 상태: 사용자 경험 확정 · 기술 설계 초안 v1 / 2026-09-16
> 범위: **소탕 기능만**. 기존 게임 한국어화 전체의 완료 여부와 별개입니다. 구현·설치하지 않았습니다.

## 목표와 대상
던전 반복 탐색을 줄이고 싶은 현재 플레이어가 남은 탐색 시간을 대체 보상으로 바꾸고 정상 하루 종료 흐름으로 넘어간다. 이미 진행한 세이브에서 사용할 수 있어야 한다.

## 확정된 사용 흐름
1. 설정 → **모드** → **소탕** 토글을 켠다. 처음에는 꺼짐.
2. 조건에 맞는 일반 던전 지도에 **자동 소탕** 버튼이 나타난다.
3. 버튼을 누르면 안내와 **취소 / 소탕 실행** 선택지가 뜬다. 기본 선택은 취소.
4. 취소하면 탐색 시간·보상·난수 상태가 그대로다.
5. 실행하면 입력을 잠그고 남은 시간에 해당하는 보상을 한 번 정산한다.
6. 실제 획득 요약을 표시하고 원작의 정상 하루 종료 경로로 이어진다. 결과 확인을 위한 추가 버튼 입력을 요구하지 않는다.

**토글을 켜거나 던전에 입장하는 것만으로 소탕이 실행되지 않는다.**

## 기능 요구사항
- FR-001: 토글 OFF이면 지도 버튼을 숨기고 입력 판정도 제거한다. 토글은 기존 던전 편의 기능처럼 공통 설정으로 유지한다.
- FR-002: 일반 탐색 던전에서 파티 인원 1~3명이고 행동 가능한 유효 동료가 최소 1명일 때만 버튼을 표시한다. 스토리·보스·특수 종점에서는 표시와 실행을 모두 차단한다. 일반 던전도 튜토리얼·전투·다른 모달·이동/맵 전환 중, 남은 시간 0이면 실행 불가. 현재 층을 표시와 지급 직전에 다시 검사한다. 원작 IsTrainingDungeon은 일반 던전 분류이므로 제외 조건으로 사용하지 않는다(DEC-007).
- FR-003: 확인창에서 대상 던전/층, 소모할 남은 시간, 현재 보상 배율과 대체 보상 방식임을 알린다. 취소/ESC/우클릭은 무변경.
- FR-004: 현재 던전·층의 원작 적/상자 보상 규칙으로 산출한다. '무한 던전의 보상 전부'를 지급하거나 미래 층을 클리어한 것으로 처리하지 않는다.
- FR-005: 전투당 순차 정산으로 중간 레벨업·개인 보너스·인원 보정·보상 배율·소지 상한을 보존한다. 상자도 원작 일반 상자 추첨 범위만 사용한다.
- FR-006: 남은 탐색 시간을 소비하고 정상 종료 처리로 인계한다. 날짜만 직접 증가시키지 않는다. 대기 동료 성장·당일 종료 이벤트를 누락하거나 중복 실행하지 않는다.
- FR-007: 더블클릭·중복 이벤트·메뉴 왕복·저장/불러오기에서 중복 지급하지 않는다. 실패 시 지급 일부만 남기고 다시 처음부터 정산하지 않는다.
- FR-008: 정산 중 표시와 실제 완료 결과를 기존 UI로 보여준다. 작동하지 않는 기존 순간 처치 알림에 의존하지 않는다.

## 비목표
스토리/보스 승리 조작, 최심층 기록 변경, 숨겨진 이벤트/CG/무기 전부 해금, 탐색 중 모든 함정·회복·동료 이벤트 재현, 기존 알림 버그 수정, 추가 보상 배율 슬라이더, 자동 세이브 덮어쓰기는 이번 범위가 아니다.

## 품질·제약
기존 푸른 발광·안개·테두리·한글 폰트를 유지한다. 판 이미지로 원본을 덮지 않는다. 원래 옵션 페이지는 건드리지 않는다. 기존 한국어화·이름 갱신·전투/경로 모드와 복구용 빌드는 보존한다. CUA 없이 정적/실행 증거를 모으고 최종 게임 조작 검증은 사용자와 한 번에 묶는다.

## 가정 및 미확정 항목
- 현재 층 기준으로 남은 시간을 환산하는 것이 v1 제안이다. 실제로 미래 층을 탐색하는 시뮬레이터는 만들지 않는다.
- **분당 전투/상자 횟수는 아직 정하지 않았다.** 원작의 보상표는 확인됐지만 시간당 획득량은 고정값이 아니다. WI-001에서 표준 탐색 정책과 계수를 근거/한계와 함께 동결한다. 임의 숫자를 원작 수치로 설명하지 않는다.
- 정상 귀환 이후 다음 날 도착까지의 호출 경로, 공통 설정 저장 위치, 보상 원자적 처리 가능성을 WI-001에서 검증한다. 실패하면 구현 전에 설계를 좁혀 수정한다.

## 프로젝트 수준 합격 기준
모든 FR이 검증 계획의 증거를 충족하고 WI-001~004가 accepted일 때만 기능 완료다. 현재 사용자 경험은 확정됐지만 기술 설계 최종 게이트는 WI-001의 미확정 항목 해소 전까지 보류다.
