## 1. 최종 런타임 spot check

정적 검증은 PASS지만 다음은 실제 화면 확인이 남았다.

- 주인공 이름 치환: 기본 이름 `료`, 사용자 지정 1자, 사용자 지정 5자
- 긴 대사와 재분할 페이지의 실제 clipping 여부
- 연속 침묵점 `・`의 실제 glyph 표시
- 모드 선택 및 빈 슬롯 `데이터 없음` 회귀 여부

새 저장·불러오기는 사용자가 호환 v2 전신 빌드에서 PASS를 보고했다. final v3는 관련 코드·STR0·PACT·EX 정적 호환 검사를 통과했지만, 이 최종 산출물의 회귀 spot check는 아직 런타임 PASS로 과장해 기록하지 않는다.

## 2. 이름 sentinel은 시각적 패딩이 아님

`료　　　　`는 엔진이 통째로 찾아 입력 이름으로 바꾸는 5-cell replacement key다. 전각공백 네 개는 시각적 간격 조절용이 아니며 ABI 일부다.

- 정적 시뮬레이션: 기본/1자/5자 PASS
- 런타임 화면: 기본/1자/5자 모두 확인 대기
- sentinel을 `료`로 축약하거나 공백을 strip하지 않는다. 일반 `료` 음절의 오치환 위험이 있다.

## 3. 폭 감사의 `review` 판정

폭 감사 파일의 최상위 `review`는 actionable overflow가 남았다는 뜻이 아니다.

- 최종 actionable safe/physical overflow: **0/0**
- overflow page: **0**
- native `・` 보존 예외: safe **3**, physical **1**
- native `・` exact 보존: **558줄 / 8,949개**
- 창 유형 미확정 54개 stable_id: 페이지 용량 검사로 보수적 PASS

연속 침묵점을 훼손하지 않는 보존 정책과 미확정 창 유형 때문에 사람 검토 상태를 유지한다. 런타임에서는 대표 `・` 장면과 긴 대사 몇 곳만 spot check한다.

## 4. 료→이즈미 말투

기존 분석에서 료가 이즈미를 대하는 일부 대사의 존댓말/반말 혼재가 남아 있을 가능성이 있다. 작품 보이스 지침은 호칭 `이즈미 씨`, 문말은 친근한 반말이다.

이번 layout v3에서는 폭 대상 712 layout/1,002 stable_id의 의미·말투를 Codex internal로 검수했지만, 전체 관계 대사 전수 재번역 작업은 아니다. 추가 교정 시 화자·인접 대화·호칭으로 수신자를 복원하고 문맥별로 고치며 기계적인 어미 일괄 치환은 하지 않는다. 현재 정적 빌드 결함이나 릴리스 blocker로 분류하지 않는다.
